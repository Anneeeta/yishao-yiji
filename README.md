# 一勺一记

把自家的拿手菜做成一本可以点菜的微信食谱。拍下成品，记下「花雕两勺，可换料酒」这样的细节。做饭前发一张菜单给家人，收回他们想吃的几道菜，就可以照着清单买菜了。

| 记菜 | 点菜 | 做饭 |
| --- | --- | --- |
| 成品相册、分步照片、可选食材与替代品 | 一张微信卡片可选多道菜，附称呼和备注 | 从点菜单打开做法，合并食材用量，勾选家中已有的材料 |

这是一个原生微信小程序。克隆仓库后，在微信开发者工具导入仓库根目录即可体验。基础画册和卡片点菜在本地运行，食谱助手按需配置自己的 API。

## 画册

用于记录自己做过的菜的原生微信小程序。首页是成品照片画廊，可按菜名、食材、分类或收藏筛选。菜谱可记录食材和用量、分步做法和照片、耗时、分量与心得。详情页可勾选已备好的食材。

在新建或编辑食谱时，可添加并选用自定义分类。首页可横滑切换分类，也可点「分类筛选」展开网格。排序支持最新添加、最早添加、最近编辑和按菜名。

## 导入微信开发者工具

1. 解压源码，打开[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)，选择「导入项目」。
2. 选择解压后直接包含 `project.config.json` 和 `miniprogram` 的文件夹。先在模拟器试用，可以选择测试号。使用自己的微信账号真机预览或上传时，导入时填写你的小程序 AppID。
3. 后端服务选择「不使用云服务」，点击「编译」。首次打开会看到四道示例，可在「备份 → 清除示例食谱」中移除。
4. 真机测试在开发者工具中点「预览」并用手机微信扫码。使用真实 AppID 时，如相册、相机或文件选择提示隐私授权，请在微信公众平台按后台提示配置《小程序用户隐私保护指引》，声明从相机或相册选择的照片、从聊天中选择的备份文件及用途。程序使用微信提供的授权界面。
5. 用真实 AppID 完成真机验证后，可在工具中上传，在微信公众平台的版本管理中设为体验版。若需要正式发布，再根据平台提示办理相关资料并提交审核。

本地画册和微信卡片点菜可以直接编译。只有长期绑定的家庭厨房需要配置云开发，食谱助手需要配置所用服务商的域名。

若开发者工具提示「在项目根目录未找到 app.json」，检查打开的 `project.config.json` 中的 `miniprogramRoot`。这个路径相对于导入目录，必须指向包含 `app.json` 的文件夹。标准源码包填的是 `miniprogram/`。

## 食谱助手

1. 在「记一道菜 → 食谱助手 → API 设置」填自己的 API Key。页面预填硅基流动示例，同域名的语音和聊天可用同一个 Key。两个服务使用不同域名时，分别填写各自的 Key。
2. 也可换成提供兼容接口的服务。Base URL 只填 API 基地址（通常以 `/v1` 结尾），再填写各自的模型 ID。转写使用 `POST /audio/transcriptions`，字段为 MP3 文件 `file`、`model`，应返回 `text`。整理使用 `POST /chat/completions`，从 `choices[0].message.content` 读取结果。[转写接口示例](https://docs.siliconflow.cn/docs/api/audio-transcriptions-post) · [整理接口示例](https://docs.siliconflow.cn/docs/api/chat-completions-post)
3. 输入做法，或录音后点「转为文字」，核对后发送。可以继续对话修改用量、替代品和步骤。草稿会区分必需、可选和替代材料，将能从口述中直接推断的准备事项放在步骤前。打开「查看草稿」核对最新版，再发送「确认」或「确认保存」。小程序会在本机新增食谱，在聊天中回报结果，并提供查看入口。聊天模型没有写入权限。
4. 真机和发布版需要在微信公众平台配置对应的 HTTPS 合法域名。整理服务加到 `request`，语音服务加到 `uploadFile`。使用预填接口时，两处均为 `https://api.siliconflow.cn`。按微信后台提示更新隐私保护指引，说明录音和转写文本会在用户操作时发给所配置的服务。录音建议在手机微信里验证。

聊天里可拍照或选图作为食谱封面。点「发送」后，照片会成为待保存封面；再发送一张可以替换。照片不发给聊天模型，只有在确认保存食谱时才复制进本机食谱库。

助手按口述顺序整理。只有原话和上下文都无法判断，且会影响复做的关键步骤，才会简短追问。用户明确记不清时，可以让助手标记待补充。

API Key 按设备保存，不打包进源码，不包含在食谱备份中。录音保存在微信临时文件区，点「转为文字」时发送。普通聊天消息会把近期文字对话及当前草稿发给聊天服务；保存确认和封面图片由小程序本地处理。关闭聊天页会丢弃该页的对话。接口费用由你配置的服务商计费。

## 家庭菜单与点菜

### 长期绑定家人的厨房

1. 主人打开「家庭菜单」，填写厨房名，选好愿意分享的菜，点「发布到我的厨房」。以后可以在这里重新发布，上一次发布的菜名会更新。
2. 在「家庭厨房 → 我的厨房」生成单人邀请，发给一位家人。对方打开卡片点「接受邀请」。邀请可使用一次，24 小时有效。给下一位家人生成新卡片时，已接受的绑定会保留。
3. 家人之后从「家庭菜单 → 家庭厨房」进入你的厨房，一次勾选多道菜，写好备注，点「提交给厨房主人」。
4. 在「家庭菜单 → 收到的点菜单」查看和刷新，每份点单独立显示。打开后能看对应的本机做法和买菜清单。厨房点单送达小程序内的收件箱，查看时刷新。

#### 部署家庭厨房

1. 用自己的小程序 AppID 导入仓库根目录，在微信开发者工具的「云开发」中选择与该小程序关联的环境。把环境 ID 填入 `miniprogram/lib/kitchen.js` 顶部的 `environment`。留空时使用微信 SDK 的默认环境。
2. 在该环境的文档数据库建立 `family_kitchens` 和 `family_orders` 两个集合。两个集合均设为**仅管理端可读写**，或对小程序客户端设置 `{"read":false,"write":false}`。对 `family_orders` 建立组合索引，字段依次为 `kitchen` 升序和 `receivedAt` 降序。
3. 在开发者工具为 `cloudfunctions` 选择同一环境，右键 `familyKitchen` 选择「上传并部署：云端安装依赖」。重新编译小程序，再上传为体验版，用两个体验账号验证发布、邀请、点菜和收件。

云函数从微信运行时获取账号身份。云端保存厨房名称、开放菜品的 ID 和名称、成员关系，以及点菜单的称呼和备注；食谱步骤、照片和助手 API Key 保存在各自设备上。[微信云函数部署说明](https://docs.cloudbase.net/recipes/add-cloud-function-wechat-miniprogram)

### 临时分享菜单卡片

1. 你在画册首页点「家庭菜单 → 准备菜单」，从自己的食谱里选菜，点「发菜单给家人」，然后在微信里选择家人或家庭群。
2. 家人打开卡片后可以一次勾选多道菜，填写可选的称呼和备注。点「查看点菜单 → 把点菜单发回去」，再选择你的微信或家庭群。
3. 你打开收到的点菜单就能看到所有选中的菜。点「收下点菜单」会把它保存在当前设备，之后可从「家庭菜单 → 收到的点菜单」打开。
4. 打开一张点菜单，点菜名或「看做法」查看本机食谱。新卡片在长度允许时携带食谱 ID，食谱改名后仍可打开。旧卡片或较长的卡片按唯一同名食谱匹配。找不到或有重名时，页面会标明原因。
5. 展开「买菜清单」即可逐项勾选已备好的材料。相同食材、可选状态及替代说明下，明确的同单位数字用量会相加，其余用量并列显示。每道菜按食谱记载的原分量算一次。收下点菜单后，勾选进度随这张单保存在本机。

菜单通过微信卡片传递，家人能看见你选中的菜名。菜单卡片记录的是发出时的菜名，修改后重新分享即可。每张最多选 32 道，实际还受菜名长度影响。大菜单可拆开分享；点菜单太长时也可复制文字发送。点菜单记录保存在本机，可从原微信卡片重新收下。

真机验证请使用你的小程序 AppID。体验版测试时，把参与的家人加为体验成员，确保他们能打开同一版本的卡片。转发在微信中由用户选择收件人并发送。

## 数据和迁移

- 每台设备保留自己的食谱。程序将正文存入小程序本地存储，将个人照片存入小程序的本地文件目录。预览版、体验版与正式版用数据前先实际确认数据可见性，重要记录先做备份。
- 在手机端打开「备份 → 生成备份文件」，将生成的全部文件发送到自己的文件传输助手或聊天。换手机后，从同一页面选择聊天里的文件逐一导入。自定义分类会随备份迁移。备份不加密，请保存到自己的会话或离线副本。
- 导入时跳过本机已有的同 ID 食谱。系统自带的原始示例可由备份里的修改版替换。没有修改或收藏的示例不占备份空间。
- 照片保留压缩版本。每道菜可有一张封面；每个步骤可加一张照片，最多 16 步。备份文件超过约 12 MiB 会自动拆分。生成和恢复备份时需要额外的本机空间。
